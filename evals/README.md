# Offline measuring instrument

Run `npm run eval` from the repository root after the project's dependencies are installed, using Node with `stripTypeScriptTypes` support (Node 22.13 or newer; verified here on Node 24). It needs no API key, reads no environment file, starts no server or browser, and refuses fetch calls. The local loader uses Node's built-in type stripping and resolves the repository's `.js` imports to TypeScript sources; it does not install anything. Exit code `0` means all checks passed, `1` means measured leaks or mismatches, and `2` means the eval could not complete. A failed run is useful evidence, not a broken command. The generated report is `docs/immersive/evidence/evals.json`.

All suites use authored fixtures. Fields beginning with `sim_` contain synthetic inputs or projected results; counts and hashes are measured. The demo extraction omits payroll, so the runner explicitly supplies a synthetic payroll assumption. This does not mean a founder confirmed it. The report contains sorted object keys, stable array ordering, and no timestamps or durations. `node evals/verify.mjs` runs the command in fresh processes with credential-like environment variables removed, compares file hashes, and checks summary length and exit codes. It succeeds when reproducibility is verified even if both evals correctly report findings.

**guard_attacks** sends hand-written and template-generated hostile replies through `checkAdvisorText`, `guardText`, and the real `guardSentences` used by future-self chat. Each surface gets its own valid placeholder table. Every category reports attempts, blocked, leaked, and exact leaking input and output. A retained harmful span is a leak even when the guard flags it: future-self returns flagged text. Numeric leaks, advice, guarantees, and false claims around valid placeholders are separate categories. Positive controls check that ordinary words and a valid figure are still accepted. This measures output filtering on a finite authored corpus, not how often a live model attacks or resists prompt injection.

**determinism** runs each demo path with and without late payment through the engine and offline swarm twice, sequentially. It compares canonical JSON and SHA-256 hashes of the complete results, and checks that fixture reviews completed. This measures replay stability of fixture code, not live model reproducibility. Fixture trace timings are part of the hashed results; their values are not copied into the evidence report.

**context_engineering** measures every graph specialist's context at every month focus for each demo path. It uses the same hop limit, context budget, and character-based token estimate as the graph module, reports full and sliced node counts and estimates, and calculates median savings by agent and path. These are estimated graph tokens, not provider token counts, full-prompt savings, faster replies, or better reasoning.

**engine_truth** independently applies every returned candidate edit and runs the engine again, checking the lowest balance and reported change. It checks delay breakpoints against an exhaustive sweep with independently shifted receipts, including no-contract, already-short and capped cases. It tests consistency of these tools with the engine, not whether the engine's business assumptions or economics are true. Survival here only means non-negative month-end cash within the model horizon.

**document_parsing** compares `proposalFor` against hand-written clauses and expectations stored in `clauses.ts`. Clear literal amounts and calendar-day terms should parse; ambiguous, conditional, business-day and multi-amount clauses should abstain. Wrong cases retain the exact clause, expected result, and actual result. This checks the text parser, not OCR, document transcription, bounding boxes, legal interpretation, or founder confirmation.

## What this does not prove

The guard is intended to stop unsupported figures; it does not prove good reasoning, and these evals may find figures that still pass. A real placeholder can be attached to a false claim. Assumptions can still be wrong. Authored clauses and attacks are not a representative sample of all documents or model replies. Nothing here establishes real business survival, investment suitability, live provider quality, browser behaviour, device performance, deployment readiness, or human outcomes. Read the findings before making a safety claim.
