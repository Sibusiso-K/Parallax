# Offline voice host prototype and blockers

This package is not wired to the HTTP routes. `LocalVoiceSessionStore` uses an in-memory Node SQLite database: 256-bit random bearer tokens and answer IDs, only SHA-256 hashes stored, short expiry, atomic generation advance, answer invalidation, revocation, and answers re-resolved from the trusted engine snapshot. Bootstrap accepts a trusted server-created snapshot only; exposing bootstrap to untrusted request data would invalidate this boundary. The bearer is a credential. Never log it, put it in a URL, return it to third parties, or treat the snapshot fingerprint as a credential. This database stores snapshot data in process memory until revoked, purged or process exit. It is not encrypted durable storage and is not shared between instances. It is unsuitable for Vercel production or for real user data; no claim of real-user authentication, privacy compliance, or production safety is made.

`wav-inspector.ts` validates bounded RIFF PCM WAV framing and duration; it does not support WebM, Ogg, compressed WAV or arbitrary media. `provider-boundary.ts` validates WAV and transcript/returned speech content around an injected transport, with sanitized errors and no retries, connections or provider credentials. This is an adapter boundary, not a real provider client. Cancellation is cooperative and an external service may continue after cancellation. Provider output can still contain inaccurate speech or transcripts; transcript confirmation and human evaluation remain necessary.

For a deployable implementation, select and provision an authenticated shared store and real identity/session system, verify atomic cross-instance revocation and generation checks, encrypt data in transit/at rest and establish deletion/retention. Build consent and revocation in the app, CSRF protections appropriate to the selected credentials, rate/cost limits, edge request limits, decoder resource isolation and a genuine provider transport with documented privacy and subprocessors. Adapt the client's current WebM/Ogg capture or deliberately capture PCM WAV; verify actual microphone and audio playback support. Run integration and concurrency tests against the chosen infrastructure, then real browser/device tests. The current fake transport, fixture responses and SQLite process test are not evidence of provider or hosted readiness.

No credential variables or live test instructions are introduced: the integration is not ready for a live test. Keep all current route wrappers fail-closed and obtain authorization for the chosen provider and usage before any external provider call.

The prototype was tested on Node v24.18.0; the repository's Node >=20 declaration does not guarantee node:sqlite availability. Logical deletion and closing an in-memory database do not establish secure memory erasure. Verify runtime support and data-handling guarantees before choosing any host.
